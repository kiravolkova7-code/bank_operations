# Проект "Bank operations"
## Описание:
Bank operations - это приложение для анализа транзакций, которые находятся в Excel-файле. 
Приложение генерирует JSON-данные для веб-страниц, формирует Excel-отчеты, 
а также предоставлять другие сервисы.

## Функционал:
Приложение имеет ряд функций:
* Функции страницы "Главная" принимает на вход строку с датой и временем в формате 
`YYYY-MM-DD HH:MM:SS` и возвращает JSON-ответ со следующими данными:

``` 
- Приветствие в формате "???",
  где ??? — «Доброе утро» / «Добрый день» / «Добрый вечер» / «Доброй ночи»
  в зависимости от текущего времени. 
- По каждой карте: последние 4 цифры карты; общая сумма расходов; кешбэк.
- Топ-5 транзакций по сумме платежа.
- Курс валют.
- Стоимость акций из S&P500.
```
* Функции "Выгодные категории повышенного кешбэка" позволяет проанализировать, 
какие категории были наиболее выгодными для выбора в качестве категорий повышенного кешбэка. 
На вход функции поступают данные для анализа, год и месяц.

* Функции "Траты по дням недели"  принимает на вход:
датафрейм с транзакциями, опциональную дату. Если дата не передана, то берется текущая дата.
Функция возвращает средние траты в каждый из дней недели за последние три месяца (от переданной даты).

## Тестирование:
Проект покрыт модульными тестами, написанными с использованием фреймворка pytest. 
Тесты гарантируют корректную работу ключевых функций и устойчивость к некорректным входным данным.

Тесты охватывают следующие модули и сценарии:
### Функции модуля "Главная":
- Тесты функции get_greeting проверяют корректность возвращаемого приветствия 
в зависимости от времени суток с помощью фикстуры freeze_time.
- Тесты функции process_transactions проверяют Поведение функции при передаче пустого DataFrame.
Корректную агрегацию данных на валидном наборе транзакций. Обработку ситуации,
когда DataFrame имеет нужные колонки, но не содержит строк данных.
- Тесты функции load_user_settings проверяют Обработку ошибки отсутствия файла настроек.
Корректную загрузку данных из существующего файла.

### Функции модуля "Выгодные категории повышенного кешбэка":
- Тест test_analyze_cashback_categories проверяет корректность основной логики функции — фильтрацию данных и расчёт кешбэка.
- Тест test_analyze_with_empty_data проверяет поведение функции при передаче пустого DataFrame.
- Тест test_no_transactions_in_period проверяет  обработку ситуации, когда в исходном DataFrame есть данные, но нет ни одной транзакции за указанный период.

### Функции модуля "Траты по дням недели":
- Тест test_analyze_success проверяет корректную работу функции при наличии валидных данных.
- Тест test_analyze_missing_columns проверяет поведение функции, если в исходном файле отсутствуют необходимые столбцы.
- Тест test_analyze_file_not_found проверяет обработку ситуации, когда указанный файл не существует.

Для выполнения тестов необходимо иметь установленный pytest. 
Запустить все тесты в проекте можно из корневой директории 
следующей командой:`pytest`

## Использование:
Запуск скрипта осуществляется из командной строки. Вот несколько примеров использования.

### - Запуск только блока "Главная"
```
python main.py --datetime "2021-12-31 16:44:00"
```
--datetime — обязательный аргумент для этого блока.
Другие блоки (--run-cashback, --run-weekdays) не указаны, поэтому они не выполняются.

### - Запуск блоков "Главная" и "Кэшбек"
```
python main.py --datetime "2021-12-31 16:44:00" --run-cashback --year 2021 --month 4
```
Выполняются оба блока. Для блока "Кэшбек" передаются год и месяц.

### - Запуск всех блоков с указанием опорной даты
```
python main.py --datetime "2021-12-31 16:44:00" --run-cashback --year 2021 --month 4 --run-weekdays --report-date "31.12.2021"
```
Запускаются все три блока. Для отчета по дням недели явно указана опорная дата в формате DD.MM.YYYY.

### - Запуск только отчета по дням недели с текущей датой
```
python main.py --run-weekdays
```
Блок "Траты по дням недели" выполнится с использованием текущей системной даты в качестве опорной. Блок "Главная" не выполнится, так как не указан --datetime.
